# 新辦公室平面圖

規劃搬寫字樓用嘅平面圖工具：畫房間同間隔、按真實清單（cm）擺傢俬、檢查擺唔擺得晒、睇建議方案，仲可以切換 3D 模型。

## 檔案

| 路徑 | 用途 |
|---|---|
| `floor-planner/index.html` | 工具本體（亦係 Claude Artifact 嗰個版本） |
| `docs/index.html` | 網上版（GitHub Pages），由 `floor-planner/build_pages.py` 產生 |
| `docs/plan-data.json` | 網上版一打開就載入嘅平面圖同建議方案 |

## 放上網（GitHub Pages）

1. Repo 嘅 **Settings → Pages**。
2. **Source** 揀 **Deploy from a branch**，branch 揀放咗呢啲檔案嗰條，folder 揀 **`/docs`**，撳 Save。
3. 一兩分鐘後，網址會係 `https://<帳戶>.github.io/<repo>/`。

注意：免費 GitHub 帳戶只可以喺 **public repo** 開 Pages，即係任何人都睇到個網頁同 `plan-data.json`。

## 網上版點樣儲資料

- 每個人嘅改動只會儲喺自己部機嘅瀏覽器。
- 想交換版本：撳「備份」匯出 JSON，對方撳「匯入」。
- 撳「重設」會返回 `docs/plan-data.json` 入面嘅版本。
- 想更新網上預設平面圖：喺工具撳「備份」，再用匯出嘅檔案取代 `docs/plan-data.json`（要保留 `schemes` 部分）。

## 方案

- 左邊「方案」入面，每個方案都係一張獨立平面圖：揀咗就可以直接改，自動儲存，唔會影響其他方案。第一次打開會揀方案 B，之後會記住你上次揀嘅方案。
- 喺方案入面撳「備份」，會將嗰個方案下載做獨立 JSON 檔；「匯入」會匯入去而家揀緊嘅方案。
- 網上版嘅「重設」只會還原而家揀緊嗰張圖。

## 改完工具之後

```
python3 floor-planner/build_pages.py
```

會重新產生 `docs/index.html`。

# 日本旅程記帳

`docs/japan-trip/index.html`：去日本旅行時記低每筆支出嘅工具，手機用得。

- **記一筆**：輸入金額，揀日圓（¥）或港幣（HK$），再揀類別（餐飲、交通、住宿、購物、藥妝、門票景點、其他）、付款方式、日期同備註。
- **切換顯示貨幣**：右上角撳「¥ 日圓」或「HK$ 港幣」，總數、每日明細同類別統計會一齊轉。
- **匯率**：撳「攞最新匯率」會由 open.er-api.com 攞市場參考價；冇網絡時可以自己輸入（例如兌換店牌價）。所有換算都用同一個匯率。
- **修改／刪除**：撳明細入面任何一筆就可以改；刪除要撳兩次確認。
- **匯出**：「匯出 CSV」有日圓同港幣兩欄，Excel 或 Google Sheets 直接開到；「複製文字總結」可以貼去 WhatsApp；「備份 JSON」同「匯入備份」用嚟換手機或者還原。
- 資料只會儲喺你部手機嘅瀏覽器（localStorage）。清除瀏覽器資料會清走記錄，所以旅程中間記得間中撳「備份 JSON」。

### 私隱

- 記錄只儲喺你部手機嘅瀏覽器，唔會上載去任何伺服器，亦冇任何追蹤或分析。
- 網頁只會連去兩個地方：Google Fonts（載入字型，Google 會見到你嘅 IP）同 open.er-api.com（只喺你撳「攞最新匯率」嗰陣）。兩個都唔會收到你嘅記錄，亦唔會收到來源網址。
- 網頁設定咗 Content Security Policy，就算有問題，都唔可以將資料傳去其他網站。
- 匯入嘅備份檔會先清理先用，偽造嘅檔案唔可以喺網頁度執行程式碼；匯出嘅 CSV 已防止 Excel 公式注入。
- GitHub Pages 上同一個帳戶嘅所有網頁共用同一個瀏覽器儲存空間，所以唔好喺同一個帳戶放唔信得過嘅網頁。
- 匯出嘅 CSV／JSON 檔案有齊你嘅消費記錄，分享之前諗清楚。

### 裝落手機（當 App 用）

呢個工具係 PWA：裝咗之後主畫面有自己嘅圖示，打開係全螢幕，冇網絡都用得（記帳、睇總數、匯出都得；只有「攞最新匯率」要上網）。

- **iPhone**：用 Safari 打開網址 → 撳下面「分享」掣 → 「加至主畫面」。
- **Android**：用 Chrome 打開，撳頁面頂嘅「安裝」，或者 Chrome 選單 →「安裝應用程式」。
- iPhone 上，Safari 同主畫面 App 嘅記錄係分開儲。裝好之後就喺 App 入面記帳；之前喺 Safari 記咗嘢，先「備份 JSON」再喺 App「匯入備份」。

網址：`https://mm7-lab.github.io/ClaudeCodeTest/japan-trip/`

App 檔案：`index.html`、`manifest.webmanifest`（名稱同圖示）、`sw.js`（離線快取）、`icon-*.png`。改咗任何檔案之後，要將 `sw.js` 入面嘅 `VERSION` 加一，手機先會攞新版本。

# 手機點餐學堂（眾心行善）

`docs/order-app/index.html`：教長者用手機點餐嘅模擬網頁，有健康燈號，仲有現場集體比賽。

網址：`https://mm7-lab.github.io/ClaudeCodeTest/order-app/`（要先開咗 GitHub Pages，見上面）

## 自己練習

- 6 課：皮蛋瘦肉粥 → 凍檸檬茶少甜 → 兩個菠蘿包 → 常餐（必選項目）→ 改錯單 → 健康午餐挑戰，另有自由練習。
- 黃色提示框會講下一步做咩，要撳嘅位會發光；可以熄提示自己試，亦可以開「🔊 自動讀」用廣東話讀出提示（視乎手機有冇廣東話語音）。
- 落單後會檢查啱唔啱，錯咗會逐項講邊度要改。完成咗嘅課會打 ✅（只儲喺嗰部手機）。
- 「🔠 特大字」可以將成個網頁放大。

## 健康資訊

- 每樣食物有「鹽、糖、油」紅黃綠燈號，揀「少甜／走甜」「汁另上」等選項時燈號會即時改變。
- 燈號係按一般茶餐廳做法嘅粗略估計，唔係營養化驗數據；價錢係虛構嘅。內容改喺 `index.html` 入面嘅 `MENU`。

## 現場比賽

1. 職員用電腦／平板（最好接投影機）打開網址 → 撳「主持比賽」→ 揀題數、每題秒數、題目類型。
2. 畫面會出 QR code 同 4 位數房號。老友記用手機相機掃 QR code（或者撳「參加比賽」入房號），揀公仔、打名（可以唔打）。
3. 撳「開始比賽」：題目同時出現喺投影機同手機，答啱又答得快分數高（每題最多 1000 分）。全部人答完或者時間到就公佈答案、解說同排行榜。
4. 最後有頒獎台，可以「同一班人再玩」。

### 連線方式

- 所有訊息經**免費公共 MQTT 伺服器**（WebSocket，`wss://`）轉送，所以**手機唔使同主持機連同一個 Wi-Fi**：用 Wi-Fi、4G／5G 都得，只要手機同電腦各自上到網。
- 主持機會揀第一個連得到嘅伺服器（`broker.hivemq.com`、`broker.emqx.io`、`test.mosquitto.org`、`mqtt.eclipseprojects.io`，按次序），並喺畫面顯示「中轉伺服器」。玩家手機會同時試晒所有伺服器，搵到主持人嗰個就用。
- 手機卡住超過 10 秒會出「🔎 連線診斷」，列出每個伺服器連唔連到，並講原因。
- 呢啲係免費公共伺服器，**冇服務保證**，亦可能被某啲網絡擋住（例如學校、公司網絡）。活動前一日請用幾部真手機、唔同網絡試玩一次。
- 我測試過 30 部模擬手機同時玩（本地伺服器），順暢；真實公共伺服器嘅速度同限制未實測。程式設咗 60 人上限。

注意：

- 主持人部機就係比賽主機，比賽期間唔好閂頁、重新整理或者瞓機。
- 玩家斷線會自動重連，重新打開網頁再撳「加入比賽」都會保留分數。
- 題目改喺 `index.html` 入面嘅 `QUESTIONS`（正確答案寫第一個，開始時會自動打亂次序）。
- 私隱：公仔、名同答案會經公共伺服器轉送（唔儲存）。房間以 4 位數房號識別，知道房號嘅人理論上都可以加入，所以請玩家用暱稱，唔好填個人資料。

### 安全設計同限制

- 網頁程式放喺獨立檔案 `app.js`，內容保安政策（CSP）只准載入本站程式，**唔准內嵌腳本**；只可以連去上面 4 個指定伺服器，其他網址一律被瀏覽器擋住。
- 所有顯示出嚟嘅名同訊息都只當純文字顯示（`textContent`），冇用 `innerHTML` 顯示用戶輸入。名會清走控制字元、文字方向覆蓋字元同零寬字元，最長 10 字。
- 主持機同手機收到嘅每個訊息都會先驗證格式、長度同範圍，畸形或者過大嘅訊息直接丟棄；玩家 ID 只接受 8–40 個字母數字。
- 網址參數 `?broker=` 只喺本機（localhost）測試時有效，公開網站會忽略，所以冇人可以用特製連結令你部手機連去其他伺服器。
- 第三方程式庫（`vendor/`）係原封不動嘅 npm 版本，附 SHA-256，見 `vendor/LICENSES.md`。
- 瀏覽器儲存只用 `orderapp.` 開頭嘅項目（記住完成咗邊課、玩家暱稱同加入比賽用嘅隨機編號）。注意 GitHub Pages 同一個帳戶下嘅網頁共用同一個瀏覽器儲存空間（日本記帳亦喺度），所以唔好喺同一帳戶放唔信得過嘅網頁。

**無法完全避免嘅風險**（公共伺服器冇權限控制，所有人都可以訂閱同發佈）：
- 知道程式碼嘅人（呢個 repo 係公開嘅）可以用工具偷睇某個房間嘅訊息（暱稱、答案），亦可以偽造訊息，例如將某玩家踢走、令所有人見到「比賽完咗」、或者灌大量假玩家令真玩家入唔到（上限 60 人）。要做到呢啲，要特登用技術工具針對你嘅房間，唔係偶然會發生。
- 所以**唔好用呢個比賽收集任何敏感或者個人資料**，名用暱稱；萬一被搗亂，主持人可以喺等候畫面撳「✕」移走假玩家，或者重新開房（房號會變）。
- 如果要做到真正防偽造，需要自己架設有帳戶權限嘅伺服器（例如 Cloudflare Workers），到時再同你商量。
